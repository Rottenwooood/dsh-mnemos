## 第 0 部分 · 术语表（先用 30 秒扫一遍，正文遇到不懂就翻回这里）

- **上下文窗口（context window）**：一次模型请求里能放进去的文字上限。超出就放不下。
- **令牌（token）**：模型计费和处理的最小单位，约等于 0.7 个汉字或 0.3 个英文单词。省 token = 省钱 + 能放更多真正有用的内容。
- **KV 缓存（KV cache）**：模型服务端为每段已处理的文字保存的中间计算结果。同样的文字如果字节完全相同，第二次可以直接复用缓存，既快又便宜。这也是"每会话冻结快照"这个做法存在的根本原因。
- **注入（injection）**：把记忆内容拼进发送给模型的文字里。
- **召回（recall / retrieval）**：根据当前的问题，从记忆库里找出相关内容。召回和注入是两件事：召回是查找，注入是把查到的放进请求。
- **稀疏检索（sparse retrieval）**：基于文字里的词做匹配。FTS5 和 BM25 属于这一类。
- **FTS5**：SQLite 内置的全文搜索索引。它能快速找出包含某些词的记录。
- **BM25**：给全文搜索结果排序的公式。它给"稀有但命中的词"更高分。
- **稠密检索（dense retrieval）**：把文字转换成一串数字（向量），用向量之间的接近程度判断意思是否相近。需要 embedding 模型。
- **向量（vector / embedding）**：文字被模型编码后得到的一串数字。意思越接近，数字串越接近。
- **RRF（Reciprocal Rank Fusion）**：把多套排序结果合并成一套的公式。规则是：某条记录在第几套排序里排第几名，就给它加 1/(常数+名次) 分，最后按总分排。合并后能取多套排序的长处。
- **快照（snapshot）**：某一时刻记忆内容的固定副本。快照一旦生成就不变。
- **冻结前缀（frozen prefix）**：每会话开始渲染一次、之后字节完全不变的注入块。字节不变才能命中 KV 缓存。
- **渐进披露（progressive disclosure）**：只注入每条记忆的一行索引（标题+关键词），全文留在库里，模型需要时再调用工具取全文。作用是在请求里只占很少的位置。
- **下钻（drill-down）**：模型用工具把某条记忆的完整内容取出来。
- **写入（write）**：把一条新记忆存进库。
- **写入门禁（write gate）**：写入前强制执行的一组检查，不通过就不允许写。
- **服务层门禁（service-layer gate）**：检查放在唯一的写入代码路径里，而不是放在工具层。工具可以被模型反复调用、可以被绕过；服务层是唯一的入口。
- **propose-only**：模型只能提交"候选"，不能直接生效。生效必须经过人工批准。
- **审批队列（approval queue）**：等待人工批准的候选列表。
- **审计（audit）**：每次写入、批准、拒绝都留一条记录，记录是谁、什么时候、写了什么、结果如何。
- **溯源（provenance）**：一条记忆记录它来自哪个会话、哪几条消息的原文。溯源存在，才能点回原文验证，也才能判断这条记忆是否可信。
- **用户锚定（user-anchored）**：一条记忆的证据来自用户自己说的话（逐字引用），而不是模型自己的推断。
- **衰减（decay）**：一条记忆随时间和使用情况降低热度，热度低的在排序里靠后。
- **幂律衰减（power-law decay）**：热度公式形如 H=1/(1+λ×Δt)^α，其中 Δt 是距离上次使用经过的时间。时间越久，热度下降越快，但永远不会降到零。
- **accessedAt**：这条记忆最后一次被使用（被召回/被注入）的时间。**updatedAt**：这条记忆最后一次被修改的时间。两者必须分开，因为合并/重写会改 updatedAt，但那不代表"这条记忆最近被用过"。
- **巩固（consolidation）**：后台把零散的短期记忆整合成更完整、更有结构的形式。也叫"做梦"。
- **场景（scene）**：一组相互关联、属于同一话题/同一次任务期间的记忆。
- **人格画像（persona / profile）**：从大量记忆里归纳出的"这个用户长期、稳定的偏好和身份"的浓缩描述。
- **负面记忆（negative memory）**：记录"某条路径不成立"（命令失败、方案被拒、接口不可用），带证据，并且当环境条件变化时自动失效。
- **记忆投毒（memory poisoning）**：攻击者往记忆库里塞伪造内容，让模型以后按伪造内容回答。
- **记忆注入攻击（memory injection attack）**：攻击者通过一次交互，让一条恶意内容被写进记忆库，之后一旦相关话题被召回，就按攻击者设定的方向回答。
- **A/B 对照**：同一组任务跑两遍，一遍开记忆、一遍关记忆，比较结果差异。
- **held-out（冻结集）**：评测用的任务在评测前锁死，不参与开发，防止开发时偷偷针对题目优化。
- **95% 置信区间（95% CI）**：真实效果"最可能落在的范围"。比只报一个点更严谨，因为单次实验有随机波动。
- **遥测（telemetry）**：记录真实使用过程中发生的事件数据（这次注入到底有没有被模型用上、用了多少 token、任务成功没有）。
- **效果账本（ledger）**：专门记录遥测数据的表，是"这个插件到底有没有用"的证据来源。
- **评分（rerank / scoring）**：召回得到一批候选后，再给候选按与问题的相关程度重新排序。
- **一致性验证（consistency verification）**：写入前检查新内容与已有内容是否矛盾，矛盾则处理而不是直接写。
- **知识更新（knowledge update）**：世界变了，记忆里旧的事实要被新的取代。评测里专门测"旧信息被覆盖后，模型答的是不是新信息"。
- **弃答（abstention）**：模型在记忆里找不到答案时，应该承认不知道，而不是编一个。

## 第 1 部分 · 调查清单 A：DSH 生态的具体仓库（26 个，逐个列）

> 每个仓库：**存储形式 | 召回/注入方式 | 写入方式 | 生命周期/遗忘 | 最值得抄的具体机制**。全部来自 `~/dsh-research/readmes/` 逐份精读。

1. **chenzheshushi-commits/dsh-evolve**
   - 存储：JSON 源 + Markdown 镜像，条目类型 fact/preference/decision/lesson/todo/note，作用域 user/project，重要度 1-3。
   - 召回：bigram-Jaccard 相似度 + FTS5 BM25，用 RRF 合并，零 token、无 embedding、CJK 正确。
   - 写入：两级门禁，判断只看不可自夸的属性（可逆性=重要度、与已确认记忆的冲突、重叠、是否锚定用户原话），**明确忽略模型自报的 kind 字段**；后台隔离 LLM 只提议不写。
   - 生命周期：强化（重复观测→计数+1、重要度升、保留更佳措辞）；**幂律冷度 H=1/(1+λΔt)^α，时间基准用 accessedAt||createdAt 而不是 updatedAt**；软删 forgottenAt 墓碑、pinned 三层保护、两阶段 prune（预览→执行，带原子领取 + ETag 过期检查）、JSONL 审计（fail-open、环状裁剪）。

3. **skepsun/dsh-engram**

## 第 2 部分 · 调查清单 B：2026 年科研论文（35 篇，逐个列，全部 2026 年提交）

> 每篇：arXiv 编号 | 论文名 | 具体机制 | 对 dsh-mnemos 的启示。全部按提交时间倒序。

### 2026 年 8 月（25 篇）

1. **2608.26983 GraphMemix: Query-Aware Evidence Forests for Long-Term Multimodal Agent Memory**
   - 机制：把记忆组织建模为"查询感知的证据森林构造"的组合优化。三步：(1) 候选图构造——通过 schema 关系和语义关系从多视角种子记忆扩展出与查询相关的原文候选；(2) 证据效用与激活成本分离——直接记忆支持与"锚定条件的关系验证"解耦，抑制冗余/冲突信息；(3) 森林优化——在"最大证据预算 + 可靠关系结构"下联合选择森林格式的上下文。
   - 启示：mnemos 的召回可以加"证据预算"概念：不是无脑取 top-k，而是在一个 token 预算内选"证据支持最充分、关系最可靠"的子集；多模态（图片/工具轨迹）也是可扩展方向。

2. **2608.26895 CoVeMem: Collaborative Vector Memory for Agentic Recommender Systems**
   - 机制：文本记忆一次只能改写一条，协作证据（对整个目录的相似度）无法翻译成句子。CoVeMem 把记忆的"协作核心"向量化：冻结的 LightGCN 用户/物品状态作为记忆库；每次决策由候选集自己取回最相关历史状态，以软 token 形式进入 LLM 上下文，旁边放一份轻量文本画像。对比对齐 + listwise 联合训练让模型学会读这些状态并排序；记忆维护零额外 LLM 调用。
   - 启示：对"用户偏好"类记忆，可以考虑向量化协同信号（谁和谁相似），而不是只存文本。

3. **2608.25577 PolyMemDB: A Polyglot Database System for AI Memory Management**
   - 机制：混合存储架构（图/向量/概率/时空），跟踪管理多种记忆类型；**概率推理引擎**用时间衰减 + 半环聚合解决长期事实冲突，提供细粒度溯源，让用户能透明地追踪推理链。
   - 启示：mnemos 的事实冲突解决可以升级为"带置信度与时间衰减的概率裁决"，而不仅是二选一替换；溯源要能回放推理链。

4. **2608.25553 When Stale Constraints Go Unchecked: Budgeted Verification Failures in Inherited Agent Memory**
   - 机制：溯源的不可变性与"哪条记录当前生效"是可变的分离。在稀缺验证预算下，被接替的旧约束仍在 77.3% 的回合里产生"陈旧一致"的决策；把预算重新分配一格给关键溯源路径，一致决策提升约 +61 到 +74 点。结论：记忆系统需要独立的"新鲜度/接替信号"，与相关性分开。
   - 启示：mnemos 需要"接替/失效信号"：一条记忆被新记忆取代时，旧的要标记为已接替，召回时排在后面或注明已失效——这正好对应 mnemos 缺的"知识更新"能力。

5. **2608.25329 HiPS: Hierarchical Personalized Strategy Co-Evolution (EMNLP'26)**
   - 机制：记忆管理策略不是静态一刀切。HiPS 把策略分成：通用策略（从跨人格轨迹提取共享原则）+ 人格增量蒸馏（为偏离普遍模式的具体用户生成专属规则）+ 跨层规则流（把广泛验证过的个人规则提升为全局、把被推翻的全局规则降级）；所有策略细化都必须锚定任务结果。
   - 启示：mnemos 的记忆管理（保留/压缩/丢弃什么）本身可以成为"学习出来的策略"，而且用户个性差异值得单独处理。

6. **2608.23471 InjecMEM: Memory Injection Attack on LLM Agent Memory Systems (COLM 2026)**
   - 机制：只需一次交互（无需读/写记忆库权限）即可把后续相关查询的回答引向预设输出。利用"先召回再生成"机制：注入物 = 检索器无关的锚（高召回的话题线索，让下游检索稳定把该记录关联到目标话题）+ 对抗命令（用梯度坐标搜索优化，对不确定的融合上下文、不同插入位置、长提示都保持有效；跨骨干联合优化研究迁移）。
   - 启示：**记忆投毒是 mnemos 必须面对的安全面**；写入路径要有能对抗"高召回锚"的防御，不只是关键词过滤。

7. **2608.23268 DG-Mem: Dual-Grained Agent Memory and Shapley Context Attribution (CLS 启发)**
   - 机制：互补学习系统（CLS）：实例级示例记忆 + 类别级 IF-THEN schema 记忆，中间用临时反思存储做构造——schema 只从抽象反思合成，绝不从示例原文生成；在线概念分类器在训练中增量扩展类别空间；Shapley 上下文归因把正确性分解到整个检索到的规则集，得到每条规则的效用，测试时按效用重加权检索；零梯度更新，可部署在闭权/端侧骨干。
   - 启示：记忆可分成"实例级"与"规则级"两粒；每条记忆可以带"它到底贡献了多少正确性"的效用分（对应 mnemos 的 ledger 升级）。

8. **2608.23152 FIRE: Multi-Agent Memory Efficient Reasoning (EMNLP'26)**
   - 机制：把仇恨言论先分解成五类（错误信息/刻板印象/阴谋论/非人化/非事实），每类映射到专门反驳风格；证据映射 + 推理轨迹标注驱动生成。
   - 启示：按类型分流处理是通用模式——mnemos 的提炼/注入也可以按记忆类型走不同处理。

9. **2608.22767 EARM: Experience-Amortized Reranking for Long-Term Agent Memory**
   - 机制：语义检索快但 embedding 相似度不等于"包含当前查询需要的证据"；LLM 重排强但每次从头对大量候选打分、结果又丢弃。EARM 把 LLM 相关分存进在线稀疏矩阵，用因果矩阵补全学习其共享结构，重排时混合"少量新观测分 + 估计分"。打分预算随经验积累下降。17.5% 候选获得直接 LLM 分时仍有效，最多 +6.62% 准确率。
   - 启示：mnemos 可以记录"这条记忆被检索出来后对任务有没有用"的历史，用它改进后续排序（记忆使用经验的复用），而不是每次检索都从零打分。

10. **2608.22752 The Compaction Cliff / Knowledge Triage (CIKM 2026)**
    - 机制：安全规则和情节日志抢同一份上下文预算，超预算时两者同速率被摘要，但只有规则需要逐字才能保持可执行。实测 Claude Code /compact 一轮保住 53% 安全规则，五轮只剩 10%（压缩悬崖）。**知识分流**：按类型分类每条知识，每类走自己的保留策略。三个确定性算子：TypeCompact（按类型保真度就地重写）、TypeDecompose（把过大主题拆分并跨分区复制在范围内规则）、TypeRetrieve（从外部存储取回且把范围内规则钉在相关性之前）。TypeCompact 每比例保留的安全规则是单次 LLM 压缩器的 2-4 倍，五轮召回 96%。
    - 启示：**mnemos 的 protocol/规则注入在长会话/压缩场景会被吃掉**；需要按类型分流的保留策略（规则逐字、情节可摘要）。

11. **2608.22310 HERO: Human-profile Enhanced Retrieval Optimization**
    - 机制：把对话历史转成可追溯的异构记忆图，**保留原始对话文本作为推理证据**（避免压缩信息丢失与改写语义漂移）；检索时从当前查询取初始锚 + 融入人格画像，用迭代图遍历自适应激活图的最相关区域。
    - 启示：mnemos 的证据（原文）要保留到推理环节；检索可以加"人格画像"作为引导信号。

12. **2608.22215 Dual-Layer Agentic Memory with Fast Write Routing and Slow Consolidation (CLS)**
    - 机制：把记忆管理移到写入阶段：成本感知的认识论路由（小→大模型级联）把输入分为不写/写新/写更新，过滤冗余；后续"写回"阶段把高价值外部记忆选择性固化为模型参数（监督微调）。1.7B/8B 级联剪掉 68% 冗余外部记忆、升级不到 50% 输入，却保留穷尽保留基线的 98% 精确匹配；周期巩固让路由器随模型认识边界扩展而自适应抑制冗余写入。
    - 启示：mnemos 的写入门禁可以加"写入路由"（这条到底值不值得写/是更新还是新写）；长期可以探讨把高频记忆固化成参数的方案（超出插件范围，但方向对）。

13. **2608.22061 IBIA: Indirect Bias Injection Attacks via Social Media Feeds**
    - 机制：代理摄入外部内容（浏览/邮件/社交摘要）并把选中信息留存记忆，这条路可被利用植入立场：注释伪装（与周围讨论一致）+ 注释水印（便于策展时识别，95.9% 检出）+ 类别锚定（让留存立场在后续相关请求下突显）。攻击后对四下游任务平均 AAR 91.2%；提出的"记忆边界防御"把它降到 80.6%。
    - 启示：外部内容摄入记忆是攻击面；mnemos 的导入/自动捕获路径需要水印/边界防御。

14. **2608.21867 MemGuard: Persisting Verifier Signals for LLM-Agent Memory Governance**
    - 机制：把验证器输出当作**持久生命周期元数据**而不是一次性过滤器：多标准打分→奖励、置信度、标签、不确定性描述符，在激活前附着到每条候选，并在检索、冲突解决、摘要、归档中复用。在 Terminal-Bench 2.0/SWE-Bench Verified/WebArena/Mind2Web 四骨干 16 组设置里全部取得最优成功指标（对最强基线 ReasoningBank 最大 +7.9 成功率点）。
    - 启示：mnemos 的每条记忆可以带"验证元数据"（这条是验证过成功还是偶然成功、置信度多少），并在写入后的检索/冲突/归档环节复用——把"质量信号"变成持久属性。

15. **2608.21810 MSM-Mem: Medical Structured Multimodal Memory**
    - 机制：医学结构多模态记忆：语义/情节/视觉三类记忆，推理期间增量更新，让医疗代理随使用进化。
    - 启示：按语义/情节/视觉分存储是通用分层模式（mnemos 目前没有视觉记忆，可留扩展）。

16. **2608.21230 Utility Under Attack: Agent Memory Poisoning and the Limits of Content Screening and Provenance Ranking**
    - 机制：持久记忆让假信息变持久。往 LongMemEval 语料投毒 1.2%，准确率从 0.850 掉到 0.300。四阶段写入筛查管线对间接提示注入召回 0.832、但误标 1.5% 良性文本，却**拒绝了 0/360 条被投毒记忆**——内容筛查无法区分假话与真话，因为那通常需要文本之外的外部依据。溯源加权检索：出厂权重与无防御统计不可区分；更强的权重只能靠排除不可信内容才恢复效用；混合溯源语料里，加性溯源项没有可用设置。**结论：应在检索时用"有界占用约束"而不是加性溯源惩罚**。
    - 启示：**投毒防御不能只靠写前筛查或溯源加权**；设计上要对"不可信来源的内容"做占用约束（限制它进入检索结果的数量/位置），而不是给它加一个权重。

17. **2608.20920 ForeDreamer: Self-Evolving Dual-Agent Memory (EMNLP'26 Findings)**
    - 机制：把原始网络证据先转成结构化记忆再预测：事实记忆（当前预测的问题相关证据状态）+ 经验记忆（跨预测轮次积累的代理经验）；主代理负责搜索与预测，记忆处理子代理用专门工具把搜索结果转成事实记忆；两条轨道演化经验记忆（既改进预测决策也改进事实记忆构造）。
    - 启示：mnemos 的"事实记忆 vs 经验记忆"分离 + 独立记忆处理子代理，是提炼流水线的更完整形态。

18. **2608.20664 DreamBench-SWE: Multi-Session Memory-Hygiene Benchmark for Software Agents**
    - 机制：多会话记忆卫生基准：后续软件任务依赖先前会话中不可推断的证据，用可执行隐藏裁判打分。结果：无外部记忆 21/180、确定性逐字事件记忆 82/180、typed+raw 参考探针 83/180、固定托管 Mem0 字面存储 97/180（0.5389）。审计结论：这是一个能区分的可执行基准，但不支持"某个外部系统机制普遍更优"的结论。
    - 启示：**评测要可执行、可区分、附诚实边界**；mnemos 的 benchmark 应参考这个的纪律（先定判据、锁证据、报告负结果）。

19. **2608.20631 Weighted Memory Tree (WMT)**
    - 机制：把执行历史组织成任务/子任务/动作的分层树，每条记忆带动态保留分；**基于事件的更新 + 基于选择的衰减**修订分数，保留有用信息、折叠完成轨迹、抑制低效用内容、保留折叠上下文入口。相比线性记忆：平均 +9.97 准确率点、prompt token 减少 32.8%；投毒实验显示它限制不可靠信息的持久与传播。核心论点：长期记忆的有效性更取决于"决定哪些信息保持激活"而不是"存得更多"。
    - 启示：mnemos 需要"保留分/激活决策"机制——决定哪些记忆在注入时保持激活，而不是全量参与。

20. **2608.19701 CAMA: Correlation-Aware Memory Arbitration**
    - 机制：多代理记忆的"记忆相关偏差"：不同代理写的记忆可能继承同一上游来源或共享偏见，被重复计数造成假多数。CAMA 把召回记忆建模为查询条件的证据组，结合神经依赖推断 + 基于溯源的符号先验估计独立证据源的有效数量；再用顺序恢复策略主动取回替代证据或追踪上游源，最小化取回成本。
    - 启示：多代理/多源记忆合并时，不能把来源相关的证据当独立证据数；mnemos 的溯源要能表达"这些记忆同源"，仲裁时要避免重复计数。

21. **2608.19652 Can Agent Memory Systems Track Evolving State? / StateMemBench**
    - 机制：定义"状态追踪"能力——事实、约束、决策在长交互中被修订后，答案必须反映当前状态而非被接替的状态；用 StateMemBench 实例化。
    - 启示：mnemos 需要明确的状态/版本语义：事实被修订后，召回要能给出"当前值"，并标明旧值已失效。

22. **2608.18066 On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification**
    - 机制：对两类基于记忆的自改进方法做重评估：多轮次量化方差、随机打乱任务顺序、暴露欠规定问题。结论：可靠性被严重低估，很多"改进"来自任务顺序/方差而非方法本身。
    - 启示：**mnemos 若宣称"自进化有效"，必须做多轮次 + 随机任务序 + 显式声明欠规定**，否则不可信。

23. **2608.17756 D2ACCI: Dual-Loop Diagnostic Protocol for Evidence-Preserving Agent Memory**
    - 机制：记忆的多阶段流水线（摄入/检索/过滤/生成）让失败难定位：端到端评测只说明"出错了"，不说明哪一阶段出错。D2ACCI 提供阶段级诊断轨迹、切片级非回归检查、配对统计比较。
    - 启示：mnemos 的评测要能定位到"是写入烂、检索烂、还是注入烂"，而不是只给总分。

24. **2608.17665 GraphWake: Memory-Mediated Polarization Cascade**
    - 机制：把代理记忆当作持续通道 + 公开讨论作为传播介质诱导群体极化（新威胁模型）。
    - 启示：记忆作为传播介质的安全性值得记录在威胁模型里。

25. **2608.16357 MELD: Merging Knowledge Across Distributed Agentic Memories**
    - 机制：让两个代理的记忆协调"同一事实两种说法""分开放的相关事实""矛盾的两种说法（不静默丢弃任何一方）"；运行时模型是知识图本身；每条进入的声明走五结果程序（哪种结果待查全，但不静默丢弃）。
    - 启示：mnemos 的同步/合并（git）需要协议级"矛盾仲裁"，而不是 git 冲突完事；冲突双方都要保留可追溯。

26. **2607.21962 Veracium: Ground Truth First, Longitudinal Evaluation, Tenure Crossover**
    - 机制：反向评测管线：先用带有效性区间、易变类、来源通道的事实清单生成种子人生脚本，再让 LLM 渲染聊天/邮件，验证器确认每个植入事实，问题从脚本机械实例化（gold 答案构造性有效）。语料含逐事实有效性区间、发送/接收信任区分、良性环境注入探针、as-of-date 问题集。对五种记忆架构对比无记忆对照（固定答题器、版本化 LLM 判官、三重复、两个时间跨度），发现**排行榜随历史长度反转**：预算策展图记忆三周领先但九周丢失被逐出内容的召回（96%→72%），而溯源类型化图升到 90%（跨族重判 p=0.031）；**写入阶段质量与下游质量强相关**（弱写事实失败 24% vs 2%）；注入抵抗力与"溯源边界能否在表示层存活"相关；分层架构两阶段最优（短跨度 96.8%）。

## 第 3 部分 · 从清单推导的完整图景（每条回指具体来源，不用"共识"）

### 3.1 结构维度：记忆不是"一条一条"，而是有层级、有类型、有图

- **层级**：热层常驻、冷层按需（meow 七层、mnemosyne BEAM 双级、self-improved L0-L3、DG-Mem 实例+规则双粒、MSM-Mem 语义/情节/视觉）。mnemos 现在是扁平的（记忆 + 规则 + protocol），没有"场景/人格"这两级。
- **类型**：事实/决策/流程/偏好/错误/洞察/交接/任务（engram 的 8 类）；user/feedback/reference/project（memory-manager）；user/agent 双轨（memento）。类型决定处理策略（FIRE 按类型分流）。
- **关系**：A-MEM（2025）动态互链、mneme 实体图、graph-memory 类型化边、HERO 保留原文的异构图、GraphMemix 查询感知证据森林、CAMA 同源去重。mnemos 无关系。
- **粒度与分页**：实例级 + 规则级（DG-Mem）；WMT 任务/子任务/动作树 + 动态保留分。

### 3.2 操作维度：写-管-读三件事

- **写（write）**：
  - 谁写：零 LLM 确定性捕获（engram）vs LLM 提炼（多数）vs 人工（memory-manager）；写路由判断"写不写/写新还是写更新"（Dual-Layer 2608.22215）。
  - 门禁：服务层不可绕过 + 判断用不可自夸属性（evolve、memento）；审批载荷带全文、被拒也留审计（memento）；验证信号持久化为元数据（MemGuard 2608.21867）；证据逐字用户原话（evolve-modes）。
  - 脱敏：写前脱敏（灵枢）；索引时脱敏（deja）；证据过滤（ReMe）。
- **管（manage）**：
  - 冲突：二选一替换升级为概率+时间衰减裁决（PolyMemDB 2608.25577）；矛盾不静默丢弃（MELD 2608.16357）；冲突→人工裁决（mnemos 已有 replacement 提案）。
  - 遗忘：幂律冷度用 accessedAt（evolve）；艾宾浩斯（meow）；事件更新+选择衰减（WMT 2608.20631）；"学会遗忘"（2603.07670）；被接替状态要有新鲜度信号（2608.25553、StateMemBench 2608.19652）。
  - 巩固：做梦/睡眠（meow、mneme、sgme、self-improved 夜间）；写回固化为参数（Dual-Layer 2608.22215）。
  - 压缩：压缩悬崖（2608.22752）——规则必须逐字、按类型分流；溯源指针替代 LLM 摘要（engram Context GC）；滚动检查点带溯源（graph-memory）。
- **读（read）**：
  - 注入形态：每会话冻结快照保 KV（meow、engram、memento、memory-standard）；渐进披露索引+下钻（engram、meow、memsearch、memory-manager）；protocol 常驻。
  - 排序：BM25/向量/RRF（self-improved、evolve、memsearch、ReMe、sgme）；经验复用排序（EARM 2608.22767）；时间感知查询扩展（LongMemEval 2025）；证据效用/激活成本（GraphMemix 2608.26983）；高精度语义门 + 不落回无关（graph-memory）。
  - 时机：用户输入关键词触发（mnemos 现状）；点动作召回（deja PreToolUse/PostToolUse）；场景门控（sgme）；会话开始 + 每步（多数）。

### 3.3 安全维度（2026 新出现的、之前没有的）

- 记忆投毒（2608.21230）：内容筛查与溯源加权都挡不住；要用**有界占用约束**。
- 记忆注入攻击（InjecMEM 2608.23471）：一次交互 + 高召回锚 + 对抗命令，就能控制后续回答。
- 间接偏见注入（IBIA 2608.22061）：外部内容摄入记忆是传播面；水印 + 类别锚定 + 边界防御。
- 极化级联（GraphWake 2608.17665）：记忆当传播介质。
- 隐私（2606.26627）：只有信息流控制能覆盖组合与跨会话泄漏。
- 记忆损坏分类与巩固前治理（SSGM 2603.11768）。

### 3.4 评测维度（2026 从"召回分"走向"状态追踪 + 多会话 + 诚实负结果"）

- 能力：抽取、跨会话推理、时间推理、知识更新、弃答（LongMemEval 2025，仍是最常被引用的五能力）；**状态追踪**（StateMemBench 2608.19652）补上"事实被修订后答当前值"。
- 方法：held-out + 95% CI（Aegis）；先植事实再生成对话防污染（Veracium 2607.21962）；多轮次 + 随机任务序 + 欠规定（2608.18066）；阶段级定位（D2ACCI 2608.17756）；可执行隐藏裁判 + 诚实边界（DreamBench-SWE 2608.20664）；跨层统一预算（2607.08032）；**排行榜会随历史长度反转**（Veracium）——必须跑两个时间跨度。
- 衡量指标：success_rate_diff、turns_to_success、tokens、injection_hit（注入内容是否真被用）、cache_hit、budget_breach、contamination、维护开销（2602.19320）。

## 第 5 部分 · 详细落地计划（P0-P3，每项：做什么 / 依据 / 怎么做）

> 排序原则：先做"证明它有用"（P0），再做"让它更省更准"（P1），再做"让它更完整"（P2），最后做"让它更安全更开放"（P3）。每一项都标注具体来源，不出现"共识"。

### P0 · 效果证据层（先立身：全类别没人做，也是立项研判的死穴答案）

**P0.1 效果账本扩展（ledger）**
- 做什么：把 `usage_ledger` 从"只记命中"扩展成"记注入是否真被用上 + 前后 token + 任务结果"。每条注入事件记录：注入时注入块的 token 数、本次会话总 token 数、该注入内容是否在后续被模型引用（近似：注入后到下次注入之间，模型输出里是否出现该记忆的关键词/摘要片段）、本轮任务是否成功（可从会话结尾的 user 反馈近似）。此外给每条记忆附加"验证元数据"：来源类型（用户原话/模型推断/导入/第三方）、写入时是否通过验证、后续是否被确认有用。
- 依据：MemGuard（2608.21867）把验证器输出当持久生命周期元数据；效果账本是 memlab 测量契约的原始数据；立项研判与《记忆品类全量参考》C.2.3 明确"ledger 是效果证据的单一数据源"。
- 怎么做：`usage_ledger` 加列 `injected_tokens`、`used`（0/1，用关键词命中近似）、`task_ok`（0/1/空）、`cache_hit`；`memories` 加 `verified`（0/1/空）与 `verified_at`；写路径（提炼/record/导入）填来源与验证状态。

**P0.2 效果评测脚本（memlab 化的自测）**
- 做什么：一个可复跑脚本，对 mnemos 跑四组测试并生成"成绩单"（JSON + Markdown）：
  1. **LongMemEval 五能力适配**：信息抽取、跨会话推理、时间推理、知识更新、弃答。用 LongMemEval 公开问题集，把"用户-助手聊天历史"换成 DSH 会话语料格式，注入 mnemos 后问同样的问题，统计五能力各自的准确率与弃答正确率。
  2. **开/关记忆 A/B**：6 个冻结 DSH 任务 × 5 个种子，同模型同 profile，两遍（开记忆 vs 关记忆），输出 `success_rate_diff + 95% CI`（Aegis 方法）、`turns_to_success`、`tokens_used`、`reworks`。任务在关记忆下也必须能完成（防止假阴性），且记忆内容不泄露任务答案。
  3. **状态追踪**：造一段"先记住 X，后来用户纠正为 Y"的会话，问"现在 X 还是 Y"，统计答对当前值的比例（StateMemBench 2608.19652 的能力定义）。
  4. **注入效率**：统计平均注入 token、注入命中率（注入内容是否真被用）、每成功任务总 token（开/关）。
- 依据：LongMemEval（2025，仍是最常用五能力）；StateMemBench（2608.19652）；Aegis 的 A/B+CI；Fragility（2608.18066）要求多轮次+随机任务序；D2ACCI（2608.17756）要求能定位到阶段（脚本报告要拆注入/检索/写入各阶段指标）；Veracium（2607.21962）要求跑两个时间跨度（脚本要支持短/长两个会话长度档）。
- 怎么做：`scripts/eval/` 下：`corpus/`（冻结语料与任务，git 跟踪）、`run-eval.mts`（跑评测、算指标、写 JSON）、`report.mts`（JSON→Markdown 成绩单）。接入 CI。成绩单链接进 README 第一屏。

**P0.3 效果仪表（管理页）**
- 做什么：管理页新增"效果"区：命中率、下钻转换率、注入命中率、token 节省（开/关对比的历史）、成功率差（历史）。数据全部来自 ledger。
- 依据：engram 的 ESR 遥测（proactivity ratio、recall hit rate、detail conversion）；deja-vu 的 stats；D2ACCI 的阶段级定位。
- 怎么做：`/mnemos/api/telemetry` 返回聚合；client 加效果卡片。

### P1 · 召回/注入机制革新（对模型实际体验影响最大）

**P1.1 渐进披露 + 冻结索引注入（最大 token 节省点）**
- 做什么：把"关键词命中直接注入全文"改成两层：**每会话冻结的索引块**（一次渲染、字节稳定、只含一行/条：`[类型] topic · 关键词`）+ **下钻工具 `memory_get <id>`**（模型取回全文）。protocol 常驻块保留。会话内对同一会话只注入一次索引（已实现 protocol 的每会话一次逻辑可复用），关键词命中只决定索引里哪几条"排前面/标星"，不再把全文塞进去。
- 依据：engram（冻结 `[ENGRAM]` 索引 + `engram_detail` 下钻，"检索≠注入"）；meow（首轮冻结块）；memory-standard（索引常驻、全文按需）；memory-manager（索引注入比全文低一个数量级）；memsearch（L1 搜索→L2 expand→L3 原文三层）；LongMemEval 把记忆设计拆成 indexing/retrieval/reading 三阶段。注入命中率评测（P0.2-4）会给这个改动一个量化前后对比。
- 怎么做：新增 `memory_get` 工具（参数 id，返回全文+溯源）；`agent/pre-step` 注入逻辑改为：每会话首步渲染索引块（内容 = 当前记忆全集的行索引，按 hits/heat 排序、按关键词命中置顶），后续不再注入全文；`memory_search` 返回行索引 + 可下钻。

**P1.2 时间感知排序 + 幂律衰减进召回**
- 做什么：召回/注入排序加 `heat = 1/(1+λΔt)^α`，Δt 用 `accessedAt||createdAt`（不是 updatedAt）；`accessedAt` 在每次注入命中时更新（已由 ledger 记录）；热力参与关键词匹配排序、`memory_search` 排序、清理失效候选排序。加"记忆强化"：重复观测同一主题时计数+1、重要度（热力权重）升、保留更佳措辞（新措辞与旧措辞里选更完整的）。
- 依据：dsh-evolve 的幂律冷度 + accessedAt 基准；meow 的艾宾浩斯衰减；WMT 的事件更新+选择衰减（2608.20631）；`updatedAt` 陷阱（合并/重写会误判为"最近用过"）是 dsh-evolve 明确指出的。
- 怎么做：`memories` 加 `accessed_at` 列（初始化=created_at，注入命中时刷新）；召回排序函数加 heat 项；强化逻辑挂在提炼/重复写入路径。

**P1.3 稠密召回（本地、可选）**
- 做什么：接入 sqlite-vec（或 Ollama 本地 embedding）做稠密检索，与现有稀疏 RRF 融合；提供"fact 增强 key 扩展"：把记忆里的关键名词额外作为索引键（LongMemEval 2025 提出的优化），以及"查询扩展"：对用户输入生成 2-3 个子查询再 RRF（零成本做法，用本地模型或规则切词）。
- 依据：self-improved / memsearch / ReMe / sgme / mnemosyne 全部是混合召回；LongMemEval 的 fact-augmented key expansion 与 time-aware query expansion。
- 怎么做：`embedding` 抽象接口（默认关闭，配置 `embeddingProvider: none|sqlite-vec|ollama`）；`service.search` 与索引注入在开启时把稠密分并入 RRF。

**P1.4 记忆互链 + 演化（A-MEM 式）**
- 做什么：`memories` 加 `links`（相关记忆 id 数组）与 `tags`；新记忆写入时（提炼/record），用一个轻量调用（或复用提炼的 LLM）生成"上下文描述 + 关键词 + 标签"，并找出与之相关的既有记忆建立链接；**演化**：命中/更新某条记忆时，刷新与其链接的记忆的上下文描述与属性（有限深度，防止级联爆炸）。管理页出血缘图（链接可视化）。
- 依据：A-MEM（NeurIPS 2025：Zettelkasten 动态索引+链接+记忆演化）；mneme 实体图；HERO 保留原文的图（2608.22310）；GraphMemix 的证据森林（2608.26983）。
- 怎么做：迁移加 `links`/`tags` 列；提炼/record 后调 `linkMemory`；血缘图接口 `/mnemos/api/graph`。

**P1.5 记忆分页心智（MemGPT/Letta 落到 DSH）**
- 做什么：把"索引驻留 + 全文按需"明确为分页：热区=每会话冻结索引+protocol；温区=关键词命中后单条下钻；冷区=全文/历史，只通过 `memory_search` 按需召回。配合 P1.1 的 `memory_get`。
- 依据：MemGPT（2023，"把记忆当操作系统分页"）；2603.07670 综述把"分层虚拟上下文"列为五个机制族之一；mnemosyne BEAM 双级。
- 怎么做：本质是 P1.1 的完整形态，无需单独表结构；文档与工具描述对齐。

### P2 · 生命周期完整化（负面、遗忘、巩固、人格）

**P2.1 负面记忆（失败路径）**
- 做什么：新表/类型记录"被证伪的路径"：规范化命令+工作目录 或 文件路径 作指纹，记录 claim（这条路不成立）、证据（退出码、错误文本、前置文件状态）、TTL。**在工具执行时拦截**：`tools/pre-execute` 时若相同尝试且前置条件未变 → deny（返回"此路径已知失败：<证据>"）；`tools/post-execute` 失败时若命中已知失败 → 附加该失败后续的修复建议。任一前置条件变化 → 事实失效 → 允许重试。成功重试 → 自动失效该事实。
- 依据：dsh-negative-ledger（证据绑定+自失效+工具执行拦截）；deja-vu（PostToolUse 失败时给出同错误之后发生了什么）；MisakaNet（E0-E4 证据分级）。
- 怎么做：新表 `negative_memory`（fingerprint/claim/evidence/witnesses/ttl/status）；hook `tools/pre-execute` 与 `tools/post-execute`（真实事件已验证存在，签名 `(exec, next) => PreToolDecision`）。

**P2.2 遗忘策略进清理与归档**
- 做什么：清理失效候选按 heat（P1.2）排序而非只按"未用未更新"；引入"归档"层（active→archived→deleted），归档可逆；"受保护"标记（pinned，不参与清理候选）。
- 依据：dsh-evolve（active→stale→archived + pinned 三层 + 绝不硬删）；WMT 的动态保留分（2608.20631）；SSGM 的巩固前治理（2603.11768）。
- 怎么做：`memories` 加 `pinned`；状态机 active/archived/deleted；`listStale` 改按 heat 排序。

**P2.3 巩固/做梦 + 场景 + 人格（金字塔 L2/L3）** — ⚠ 已实现后移除：评审决定"人格与源记忆同源重复注入=纯冗余、场景无运行时作用且都不可编辑"，`scenes`/`persona` 表与全部入口已删除。教训：抽象层必须有"批准即取代源记忆"的接替语义和编辑能力，否则不如不做。
- 原始方案（2026-08 曾落地后删除）：
- 做什么：后台整合任务（空闲或夜间、用独立提炼模型）把零散记忆做三件事：(1) **场景分组**：把同话题/同任务期间的记忆归组，生成场景摘要；(2) **项目摘要**：把某工作区的反复模式抽成高层概括；(3) **人格画像**：从用户偏好/决策/纠正里归纳"这个用户长期稳定的偏好、身份、工作要求"的证据加权画像，注入时按任务相关性投影。整合只产生"候选"，进审批队列（沿用现有 propose-only）。
- 依据：self-improved（L0-L3 金字塔 + 版本化人格）；meow（做梦 3 轮整合：原子→话题→项目）；mneme（autoDream + 睡眠）；sgme（分层蒸馏 + 人格=证据加权倾向）；2605.06716（Experience 阶段：跨轨迹抽象）。
- 怎么做：新增 `scenes`、`persona` 表；`registerScheduledDistill` 改为空闲/夜间触发的整合任务；整合输出复用审批队列。

**P2.4 知识更新/接替语义**
- 做什么：事实被新事实取代时，旧记忆标 `superseded`（保留原文 + 接替链），召回时旧值排在后面并注明"已被新值取代"；冲突裁决从"二选一替换"升级为可保留双方 + 标注当前值。
- 依据：StateMemBench（2608.19652）；Stale Constraints（2608.25553，"需要独立的新鲜度/接替信号"）；MELD（2608.16357，矛盾不静默丢弃）；PolyMemDB（2608.25577，概率+时间衰减裁决）。
- 怎么做：`memories` 加 `supersedes_id`/`superseded_by_id`；替换提案批准时写接替链；召回时对 superseded 条目降权并标注。

### P3 · 安全、开放协议、工程可靠性

**P3.1 投毒与注入攻击防御**
- 做什么：三层：(1) **有界占用约束**：不可信来源（第三方/导入/未验证外部内容）的记忆，在召回结果里限制数量与位置，而不是给它们一个溯源权重（2608.21230 明确说加性溯源权重没有可用设置）；(2) **来源边界防注入**：注入内容带来源标记块，模型可见"这是记忆、来自哪个会话/来源"，降低被当作"当前指令"的概率（Veracium 发现注入抵抗力与溯源边界能否在表示层存活相关）；(3) **对抗命令检查**：对"外部内容→记忆"的摄入路径（导入、网络内容捕获）做水印/类别锚定检测（IBIA 2608.22061 的水印策展思路）。
- 依据：2608.21230（有界占用约束）；InjecMEM（2608.23471，单次交互即可控制后续回答）；IBIA（2608.22061）；SSGM（2603.11768 记忆损坏分类）；Veracium（2607.21962 注入抵抗力与溯源边界）。
- 怎么做：`memories` 加 `trust`（trusted/untrusted）+ `source_kind`；召回后处理加占用约束；注入渲染加来源标记头。

**P3.2 开放测量契约 + conformance + 合并仲裁**
- 做什么：实现 `recall/get/state/probe` 四个函数作为开放 ABI + 一组 conformance 测试（验证是真实现而非空壳）；把 `ctx.mnemosBus` 三原语对齐这套契约并文档化；git 同步升级为"合并仲裁"：拉取冲突时双方都保留可追溯（各自带来源），而不是 git 覆盖（MELD 2608.16357 的五结果程序精神）。
- 依据：立项研判（开放记忆总线 + 测量契约是差异化核心）；memento conformance suite；MELD（2608.16357）。
- 怎么做：`src/dsh/adapter.ts` 实现四函数；`scripts/conformance.mts` 跑 conformance；bus 文档补齐。

**P3.3 压缩感知（防 protocol/规则被压缩吃掉）**
- 做什么：把 protocol/规则注入内容标记为"逐字保留"级别，配合 DSH 压缩时不让它们被同速率摘要（2608.22752 的知识分流）；可选：用溯源指针替代压缩摘要（engram Context GC）。
- 依据：2608.22752（压缩悬崖：规则五轮只剩 10%）；engram Context GC。
- 怎么做：`agent/request` 或注入块加保留标记；文档说明与 DSH 压缩的交互。

**P3.4 工程可靠性**
- 做什么：P0.2 评测进 CI；schema 正式迁移路径（版本化迁移，替代现在的 ALTER 补列）；e2e 覆盖 eval 脚本；README 双语 + 成绩单 + 对比表。
- 依据：2602.19320（要量化记忆维护开销、防基准饱和、报骨干）；2606.24896（依赖的治理/许可当架构变量——embedding 依赖要选可控项）；DreamBench-SWE（2608.20664，诚实边界）。
